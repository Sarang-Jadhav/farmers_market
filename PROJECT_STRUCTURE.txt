## 🔐 SECURITY ARCHITECTURE

```
AUTHENTICATION FLOW
═══════════════════════════════════════

1. User registers
   ├─ Email validated
   ├─ Password hashed with password_hash()
   └─ Role selected (farmer/customer)

2. User logs in
   ├─ Email checked in database
   ├─ Password verified with password_verify()
   ├─ Session created
   └─ Redirected based on role

3. On every protected page
   ├─ Session validated
   ├─ Role verified
   └─ Redirected if unauthorized

4. Logout
   └─ Session destroyed
```

## 💾 DATABASE SCHEMA

### users Table
```sql
id (INT, PK)
name (VARCHAR 100)
email (VARCHAR 100, UNIQUE)
password (VARCHAR 255, HASHED)
role (ENUM: farmer/customer)
created_at (TIMESTAMP)
```

### products Table
```sql
id (INT, PK)
farmer_id (INT, FK → users)
name (VARCHAR 100)
description (TEXT)
price_per_kg (DECIMAL 10,2)
quantity (DECIMAL 10,2)
created_at (TIMESTAMP)
```

### cart Table
```sql
id (INT, PK)
user_id (INT, FK → users)
product_id (INT, FK → products)
quantity (DECIMAL 10,2)
added_at (TIMESTAMP)
UNIQUE(user_id, product_id)
```

### orders Table
```sql
id (INT, PK)
user_id (INT, FK → users)
total_price (DECIMAL 10,2)
order_date (TIMESTAMP)
```

### order_items Table
```sql
id (INT, PK)
order_id (INT, FK → orders)
product_id (INT, FK → products)
quantity (DECIMAL 10,2)
price (DECIMAL 10,2)
```
